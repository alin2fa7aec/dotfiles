# 文章スタイルの詳細

`SKILL.md` の規則の例と、判断に迷う場合の扱いをまとめる。  
節の見出しは `writing-lint.nu` の指摘に付く規則名と揃えてある。指摘を受けたら同じ名前の節を読む。

## 記号

規則1に挙げたもの (矢印、括弧、注記、丸数字、em dash、全角英数字、全角スペース) に加え、次も置き換える。

<!-- writing-lint: off -->
| 書かない                                   | 書く                                                         |
| ------------------------------------------ | ------------------------------------------------------------ |
| ⇔ ↔                                        | <->                                                          |
| ⇒                                          | ->                                                           |
| ： ！ ？                                   | : ! ?                                                        |
| ― (U+2015), – (en dash), ‐ (U+2010)        | 文を分けるか、「:」や ( ) で書き換える。語をつなぐなら -     |
| ～ 〜                                      | 範囲なら - (「0-2箇所」)、「約」の意味なら語で書く           |
| その他の全角 ASCII 記号 (＃ ％ ＆ ＋ ＝ ［ ］ ＜ ＞ など) | 対応する半角記号                                |
<!-- writing-lint: on -->

## 改行

```text
NG (文節の途中で折り返している):
/// DeviceLink, FirmwareProfile など、特定のペリフェラルに紐づかない
/// Meta 系の送信はこのすべてのポートに対して行う。

OK (1文1行):
/// DeviceLink, FirmwareProfile など、特定のペリフェラルに紐づかない Meta 系の送信はこのすべてのポートに対して行う。
```

## 行末

markdown では単に改行してもレンダリングした際には改行されない。段落の途中で行を分けるなら、行末にスペースを2つ書く。

## 太字

規則3のとおり。目安を超えると、lint は太字のあるすべての行を指摘する。hook では、太字のある行を編集したときだけ指摘が届く。

## スペース

数字のあとに助数詞や単位が続くときは、それが日本語でも英字でも % でもスペースを入れない。

```text
NG: フェーダーが 1 本 / タイムアウトは 30 秒 / 3.5 mm のストローク / 8 px の余白 / +10 dB / 20 % の負荷
OK: フェーダーが1本 / タイムアウトは30秒 / 3.5mm のストローク / 8px の余白 / +10dB / 20% の負荷
```

英字の単位や % を伴う数字 (`4byte`, `16ch`, `3.5mm`, `20%`) は、全体で1つの英単語として扱い、前後の日本語との間に半角スペースを置く。  
日本語の助数詞を伴う数字 (`1本`, `30秒`) は日本語の語であるため、前後の日本語と続けて書く。

```text
NG: CRC-32 の4byte で / 1つあたり16ch を受け取る / 依らず32bit固定とする / 全体の20%を占める
OK: CRC-32 の 4byte で / 1つあたり 16ch を受け取る / 依らず 32bit 固定とする / 全体の 20% を占める
```

数字が単位を伴わず独立した語として立つ場合は、英単語と同じ扱いでスペースを置く。例: 「Qt 5.12 系」「MR 1234 を見る」

ラテン文字が日本語に接尾して一語を成す略記の内部には、スペースを置かない。例: 「ソフトG」「電気G」(ソフトウェアグループ、電気グループの略)。  
スペースは文字種の境目ではなく語の境目に置くものであり、これは数字と助数詞の間を空けないのと同じ理由による。  
判定は音読して区切るかどうかによる。「ソフトG」は続けて一語として読むため置かない。「U2S のポート」は「U2S」が独立した語であるため置く。  
lint が例外として扱う略記は `writing-lint.nu` の `ABBREV_SUFFIXES` に列挙したものだけである。新しい略記を使うならそこに足す。

## 句読点

句読点は「、」「。」に統一し、全角の「，」「．」は使わない。複数の要素を列挙するときの区切りには ", " を使い、「・」は使わない。例: 「P-FDC2, P-MD2, P-HR1 の3つの SubCPU を対象とする」  
「・」は外来語の複合語の区切り (「ユーザー・エージェント」) にだけ使う。

## 長音

カタカナ語の末尾長音は付ける (エンコーダー、ユーザー、サーバー)。lint は落としやすい語だけを見ており、網羅していない。

## nu が無い環境での検査

`writing-lint.nu` を使えない環境では rg で代用する。  
これは lint の簡易版であり、長音、改行、行末、太字は検査しない。また、コードブロックやコメント以外の行も対象になるため、誤検出はその都度判断する。

```
rg -n '[⇔↔→←⇒※—―–‐〜①-⑳\x{3000}\x{FF01}-\x{FF5E}]' <対象ファイル>
rg -n '[0-9] ([a-zA-Z]|%)' <対象ファイル>
rg -n '[0-9] (本|個|回|件|台|枚|つ|人|秒|分|時|日|月|年|倍|度|割|番|行|列|桁|文字|ページ|箇所|段階|種類)' <対象ファイル>
rg -n '[ぁ-んァ-ヶー一-龠々][0-9.]+([a-zA-Z]|%)|[0-9]([a-zA-Z]+|%)[ぁ-んァ-ヶー一-龠々]' <対象ファイル>
```

1本目が禁止記号 (全角 ASCII はまとめて範囲で指定)、2本目が数字と英字の単位や % の間のスペース (`3.5 mm`, `20 %`)、3本目が日本語の助数詞 (`1 本`)、4本目が単位付きの数字と日本語の間の欠けたスペース (`の4byte`, `32bit固定`, `20%を`)。

`grep` ではなく `rg` を使う。  
`grep` は locale が UTF-8 でないと日本語の文字クラスをバイト単位で解釈し、ほぼすべての行を誤検出する。Windows の Git Bash では `LANG` が空であることが多い。

`cd` などと連結せず rg 単体で実行する。  
permission の allow ルールは前方一致で判定されるため、連結すると毎回確認を求められる。

出力ゼロが正。なお本ファイルの「記号」の表は禁止記号を例示しているため、本ファイル自身は検出対象から除く。
